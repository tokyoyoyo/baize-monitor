# 背景知识

## 项目背景

在 AI 技术快速发展的今天，企业对算力的需求呈爆发式增长，算力中心的建设成为企业数字化转型的核心基础设施。随着 AI 模型规模的扩大和训练需求的增加，物理服务器数量激增，算力中心的规模和复杂度也在不断提升。传统的监控工具在面对这种新环境时，暴露出诸多痛点：

- **硬件监控不足**：传统监控工具往往专注于系统和应用层面，对硬件层面的监控不够深入，无法及时发现硬件故障隐患
- **告警准确性低**：大量的误报和漏报，导致运维人员疲于应对，真正的问题反而被忽视
- **监控孤岛**：不同设备和系统使用不同的监控工具，形成监控孤岛，无法实现统一管理
- **扩展性差**：难以适应快速增长的算力中心规模和多样化的硬件设备

BaiZe 监控平台正是在这种背景下应运而生，专为 AI 时代的算力中心设计，聚焦于硬件监控和告警，通过整合多种监控技术，为企业提供统一的监控视图和可灵活扩展的异常检测能力。

## 监控系统的重要性

在现代 IT 环境中，监控系统扮演着至关重要的角色：

- **实时监控**：及时发现系统异常和性能瓶颈，确保业务连续性
- **故障预警**：提前识别潜在问题，避免故障发生，减少停机时间
- **性能优化**：分析系统性能数据，优化系统配置，提升资源利用率
- **容量规划**：基于历史数据，合理规划系统容量，避免资源浪费
- **安全保障**：监控系统安全事件，及时响应安全威胁，保障系统安全

对于 AI 算力中心而言，监控系统的重要性更加凸显。算力中心的硬件设备价值高昂，一旦发生故障，不仅会造成巨大的经济损失，还会影响 AI 模型的训练和部署进度，进而影响企业的业务发展。

## BaiZe 监控平台的特点

BaiZe 监控平台具有以下特点：

- **双视角监控**：结合 BMC 带外观察（被动告警）和 Agent 主动检测，实现全方位的硬件监控
- **硬件深度监控**：专注于硬件层面的监控，包括 CPU、内存、磁盘、网络等硬件组件的详细信息和状态
- **配置化解析引擎**：通过前端页面配置 OID 映射关系，无需修改代码即可接入不同厂商、不同系列服务器的 BMC 告警，解决了各厂商 trap 格式不统一的行业难题
- **智能厂商识别**：基于企业 OID 自动识别设备厂商，自动匹配对应的告警解析器，实现告警的自动化处理
- **告警自动关闭**：支持配置告警自动关闭策略，当设备发送恢复通知时自动关闭对应告警，减少运维负担
- **组件级关联分析**：支持组件级别的告警关联，可识别同一组件的关联告警，帮助快速定位问题根因

## 技术栈选择

BaiZe 监控平台采用以下技术栈：

### Agent 端
- **后端**：Go 语言，高性能、高并发，适合处理大量的监控数据
- **监控**：Prometheus client_golang，用于暴露监控指标
- **网络**：标准 HTTP 库，用于构建 API 服务
- **系统工具**：通过调用系统命令（如 dmidecode）获取硬件信息
- **第三方库**：gopsutil，用于跨平台获取系统信息

### Server 端
- **后端框架**：Gin 框架，用于构建 RESTful API 服务
- **数据库**：PostgreSQL，用于存储告警数据、用户信息和配置信息
- **嵌入式组件**：Prometheus（指标收集）、Grafana（数据可视化）

## 核心概念解释

为了让更多用户了解 BaiZe 监控平台，以下是一些核心概念的解释：

### Agent
Agent 是部署在被监控主机上的轻量级客户端，负责收集主机的硬件信息、系统指标和异常检测数据。Agent 通过 HTTP API 暴露采集的数据，供 Server 端或 Prometheus 等监控系统采集。

### Server
Server 是监控平台的服务端组件，负责接收和处理来自 Agent 的数据，提供 Web 界面和 API 接口，以及处理 SNMP trap 等功能。

### SNMP (Simple Network Management Protocol)
SNMP 是一种网络管理协议，用于监控网络设备的状态。BaiZe Server 端支持 SNMP 协议，可接收来自服务器 BMC 和网络设备的 trap 告警。

### Trap
Trap 是 SNMP 协议中的一种机制，当网络设备或服务器 BMC 检测到异常时，会主动向监控系统发送告警信息。BaiZe Server 端支持接收和处理来自不同厂商的 SNMP trap。

### BMC (Baseboard Management Controller)
BMC 是服务器主板上的独立管理控制器，可监控服务器的硬件状态（如温度、电压、风扇转速等）。当硬件发生异常时，BMC 会通过 SNMP trap 主动发送告警。

### OID (Object Identifier)
OID 是 SNMP 协议中用于标识管理对象的分层标识符。不同厂商的设备使用不同的 OID 来表示告警级别、告警内容、告警时间等信息。BaiZe 通过配置 OID 映射关系来解析不同厂商的告警。

### 异常检测
异常检测是指通过分析监控数据，识别出与正常模式不符的异常情况。BaiZe Agent 端实现了基于规则的异常检测功能，可检测 CPU、内存、磁盘、网络等方面的异常。

**可扩展的检测器架构**：
- **插件化设计**：采用接口驱动的插件化架构，检测器与框架解耦
- **自动注册机制**：通过 `init()` 函数自动注册新检测器，无需修改核心代码
- **统一接口规范**：实现 `Detector` 接口（`CheckItemName()` 和 `Detect()`）即可添加新检测器
- **独立开发部署**：每个检测器独立成文件，可按需编译到 Agent 中，不影响其他功能
- **示例模板**：提供标准检测器模板（如 `example_detector.go`），降低开发门槛

### Prometheus
Prometheus 是一款开源的监控系统，用于收集和存储时间序列数据。BaiZe Agent 通过 Prometheus client_golang 库暴露监控指标，可被 Prometheus 采集和存储。

## 白泽的硬件监控实现

BaiZe 监控平台通过以下方式实现硬件监控：

### 1. 双视角监控

**BMC 带外观察（被动告警）**：
- 服务器 BMC 检测到硬件异常时，主动发送 SNMP trap 告警
- Server 端接收 trap 后，通过配置化的解析引擎自动识别厂商并解析告警内容
- 支持告警自动关闭：当 BMC 发送恢复通知时，自动关闭对应告警
- 支持组件级关联：识别同一组件的关联告警，帮助定位根因

**Agent 主动监测**：
- 部署在主机上的 Agent 定期采集硬件信息和系统指标
- 基于规则的异常检测：检测 CPU 核心数不匹配、内存 ECC 错误、磁盘 IO 错误、网络链路断开等异常
- 通过 HTTP API 和 Prometheus 格式暴露采集的数据

### 2. 配置化 BMC 告警解析

BaiZe 的核心优势在于配置化的告警解析引擎：

- **无需修改代码**：通过前端页面配置即可接入新厂商的 BMC 告警
- **OID 映射配置**：配置告警级别、告警内容、告警时间、告警组件等核心字段的 OID
- **级别映射**：将厂商特定的告警级别映射到标准级别（Critical、Warning、Info、Notification）
- **自动关闭策略**：配置告警索引和状态 OID，实现告警自动关闭
- **组件映射**：配置组件关键词映射，实现组件级告警关联分析

### 3. 智能厂商识别

- 基于企业 OID 自动识别设备厂商
- 自动匹配对应的告警解析器
- 支持多厂商设备混合部署环境

### 4. 多方式数据采集

- **Linux 系统**：优先使用 dmidecode 命令获取详细的硬件信息
- **通用方式**：使用 gopsutil 库获取跨平台的系统信息

### 5. 模块化采集器

- **CPU 采集器**：收集 CPU 的型号、核心数、频率等信息
- **内存采集器**：收集内存的容量、使用情况等信息
- **磁盘采集器**：收集磁盘的容量、使用情况等信息
- **网络采集器**：收集网络接口的配置、流量等信息

### 6. 基于规则的异常检测

- **CPU 异常检测**：检测 CPU 核心数不匹配、超线程异常禁用等
- **内存异常检测**：检测内存 ECC 错误等
- **磁盘异常检测**：检测磁盘 IO 错误等
- **网络异常检测**：检测网络链路断开等

### 7. 数据暴露

- 通过 HTTP API 暴露采集的数据
- 通过 Prometheus 格式暴露监控指标
